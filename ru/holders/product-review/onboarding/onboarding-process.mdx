1. User clicks on the banner on the wallet's main screen. The wallet redirects the user to the Holders WebApp.

4. Phone number entry and confirmation (OTP). The user enters their phone number and confirms it using a code received via SMS message. By default, the system suggests the country code selected by the user during the pre-onboarding stage, however the code can be changed by clicking on the corresponding country flag. Confirmation code delivery is implemented in partnership with [Twilio](https://www.twilio.com/en-us) service. Upon phone number confirmation, a user profile is created in the Holders database and Holders policies are accepted — Privacy Notes. The version of accepted policies is also saved in the service database.

   - **Resend code** — function for resending the authorization code with a 40-second interval. The number of requests is limited to five per day, however this limitation can be removed by the Backoffice system administrator on the user management page.
   - **Didn't receive the code?** — function for opening a modal window with an informational message: "**Not received the code?** Check your number, it may have been entered with an error. It is also possible that airplane mode is turned on or there is no access to the operator's network. Or write to support, we will try to help you" and the ability to contact support through the integrated Intercom service.

5. Email address confirmation. The user enters an address and clicks continue. The system checks the address for fraud using the external service [_Postmark_](https://postmarkapp.com/). After successful verification, the user receives an email with a six-digit numeric confirmation code that must be entered in the corresponding field. Alternatively, the user can confirm the email address by clicking a special button in the received email. If the email was not received, the user has the option to return to the email address entry screen and repeat the process. Note: there is a limit of no more than 3 emails with confirmation codes within 24 hours.
6. Beginning verification. The user arrives at a screen with an offer to complete verification and clicks Continue.

# Profile log in

The user logs into an existing account within the Holders extension in the partner wallet.

- Login by phone number
- Login by seed phrase

## Login by phone number

Used when the user has previously used the service or wants to link an additional wallet address to their profile (the number of wallets linked to one profile is unlimited).

1. The user navigates to the Holders application from the wallet interface. The transition design depends on the partner: when transitioning from the Tonhub application, the user clicks on the banner on the wallet's main screen.
2. The user selects their country of residence by scrolling through the list of flags or entering the country name in the search field. The system supports input of both full country names and abbreviations (for example, UAE, USA) in any language. When logging into an existing account, we already know the user's country, however until the phone number is entered, it's unclear whether the user is attempting to log into an existing account or create a new one.
3. The user enters the phone number they previously used in the service. After clicking the "Continue" button, the user proceeds to the number confirmation page. At this stage, automatic acceptance of the current _Privacy Policy_ also occurs.
4. Upon correct entry of the confirmation code, the user is taken to the page of the last created account.

## Login by seed phrase

Used when the user knows the seed phrase from the TON wallet linked to the profile in Holders. After entering the seed phrase, the profile opens along with the wallet. To log into the profile, you need to go to the "Cards" section at the top of the wallet and then click the "Continue" button — the user will be taken to the page of the last created account.
