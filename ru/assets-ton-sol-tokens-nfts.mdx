# Поддерживаемые активы

Tonhub отображает и поддерживает следующие типы активов: нативный [TON](https://ton.org/), [tokens](https://docs.ton.org/develop/dapps/asset-processing/jettons) в сети TON, а также [SOL](https://solana.com/) и [tokens](https://spl.solana.com/) в сети Solana. Ниже описано, как эти активы показываются, откуда берутся данные и какие ограничения существуют.

# Токены в сети TON

У каждого token есть:

- **Master contract** — определяет тип token, его symbol, name и количество decimal places.
- **Token wallet** — контракт по адресу пользователя, в котором хранится баланс этого token.

### Как Tonhub отображает токены

Приложение получает список tokens и balances по TON address с backend Tonhub через запрос **Hints Full**, путь `/hints/full/{address}`. В ответе приходит список token wallets с balances и metadata. Пользователь не может вручную "добавить" или "удалить" token в смысле изменения server list: отображаются только те tokens, для которых у вашего address есть token wallet и которые вернул API. Скрытие или пометка как spam влияет только на отображение внутри приложения, см. ниже.\
Для каждого token показываются:

- **Name и symbol**, то есть `name` и `symbol`, из metadata master contract, через cache или Tonhub API.
- **Amount**, то есть balance, с учетом decimals.
- **Icon**, то есть image, если она передана в metadata API.

### Gasless для токенов

Для некоторых tokens, например [USDT](https://tether.to/), при использовании [W5 wallet](https://docs.ton.org/participate/wallets/contracts#wallet-v5) доступна оплата fee прямо в этом token, то есть gasless. Приложение получает список таких tokens из gasless config на сервере. Подробнее об этом см. в разделе [Receiving and Sending](/receiving-and-sending-transactions).

# Спам и риски: маркировка токенов и адресов

### Проверка на backend

Для tokens API может возвращать поле **verification**, например `whitelist`, `blacklist` или `none`, а также флаг **isScam** для wallet. Это используется для визуального выделения подозрительных tokens или addresses, например через пометку `SCAM` в интерфейсе token или badge на avatar во время transfer.

### Ручной список (deny list)

Пользователь может добавлять addresses в "manual spam filter", то есть deny list, в настройках. Такие addresses показываются с пометкой spam, badge на avatar, при отправке, но **сама отправка не блокируется** — пользователь все равно может подтвердить transfer. То есть защита от phishing и мошенников реализована в виде предупреждения, а не жесткого запрета.

### Только TON

Логика spam filter, включая автоматическую пометку по сумме или comment, известные spam wallets и deny list, в Tonhub применяется **только к TON и tokens**. Solana transactions, то есть SOL и SPL tokens, как spam **не маркируются** и через этот фильтр не проходят.

# Solana: SOL и токены

[**SOL**](https://solana.com/) — нативный баланс Solana, он показывается в разделе Solana wallet. Данные запрашиваются через RPC, это balance и history.\
[**Tokens**](https://spl.solana.com/) - приложение получает список tokens по Solana address пользователя с backend Tonhub через **POST** на `/solana/tokens/mainnet`, либо `devnet`, с body `{ address }`. В ответе приходит массив tokens с полями `address`, это `mint`, `symbol`, `name`, `decimals`, `logoURI`, `amount`, то есть balance, и так далее.\
**Кто решает, какие tokens показывать:** backend. Приложение отображает только то, что вернул API; фиксированного списка "supported" tokens в коде приложения нет. Ограничений на отображение тоже нет, поэтому по умолчанию Tonhub показывает все tokens.\
Spam filter и deny list для Solana в Tonhub **не используются** — маленькие или подозрительные Solana transactions как spam не помечаются.

# Управление списком активов

В кошельке есть два раздела для отображения tokens:

- **Savings accounts** — этот раздел по умолчанию содержит известные stablecoins и нативные currencies. Редактировать его нельзя.
- **Tokens** — этот раздел показывает все остальные tokens блокчейна TON. Этот раздел можно редактировать.

### Редактирование раздела Tokens

На token card доступно действие `Hide`. Скрытый token исчезает из основного списка и перемещается в отдельный блок **Hidden tokens**, который можно свернуть или развернуть. Восстановить token можно прямо из этого блока: кнопка `Show` на карточке скрытого token возвращает его в основной список. Настройка сохраняется локально и синхронизируется через cloud по ключу `jettons-disabled`.\
Для tokens, привязанных к [Ledger wallet](https://www.ledger.com/), работает отдельный список скрытых tokens с похожей логикой: скрытие перемещает token в hidden block, а кнопка `Show` возвращает его назад.\
Функция скрытия и отображения отдельных tokens в SOL не поддерживается — показываются все tokens, которые вернул API.\
Порядок tokens определяется автоматически: учитываются verification, например `verified`, наличие balance, exchange rate и другие параметры. Функции `pin` или `favorite`, которая поднимала бы выбранный token наверх списка, в приложении **нет**.
