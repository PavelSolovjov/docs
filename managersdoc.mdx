## What is Holders?

[**Holders**](https://holders.io/) is a revolutionary fintech solution that will transform your crypto wallet into a source of additional income! Integrate Holders and offer users the ability to open decentralized accounts and issue real bank cards directly in your application. Earn commission from every purchase your users make, increase retention and expand functionality without additional licenses. Your users will be able to spend cryptocurrency anywhere cards are accepted — from coffee shops to online stores.\
Users will be able to:

- Open decentralized accounts
- Issue bank cards
- Top up accounts
- Pay for purchases in any stores that accept cards with any convenient cryptocurrency, even if your application doesn't support it
- Add card to Apple Pay / Google Pay
- Track transactions and manage limitsTrack transactions and manage limits

## Integration Options

1. **WebView (fast)** — a Holders web application with customizable color scheme opens inside the mobile application.
   1. Timeline: from 2 weeks
   2. Ready-made UI from Holders with color scheme selection option
   3. Minimal development
   4. Automatic updates
2. **Full API (flexible)** — integration approach where the partner implements their own user interface for Holders functionality within their mobile application.
   1. Timeline: from 8 weeks
   2. Individual user interface adapted to your application architecture
   3. Full control
   4. UX customization

## Integration Stages

### Integration Roadmap (for WebView integration)

1. Integration preparation
   1. Partnership agreement signing
   2. Staging API access
   3. Entry point design approval
2. Development
   1. TonConnect authentication implementation (for TON integration)
   2. WebView component integration
   3. Authorization token storage
   4. UI for entry points (banners, buttons)
   5. Deep links handling
   6. Push notifications (optional)
3. Testing
   1. Functional - verification of all user flows on Staging
   2. Integration - WebView, deep links, notifications
   3. UX testing - verification on real devices
   4. Regression - verification that core functionality is not broken
4. Launch
   1. Switching to Production API
   2. Final testing on Production
   3. Application update release
   4. Active monitoring of launch metrics
